0-1. この教材も、GitHub で作られています

最初に、ひとつ伝えておきます。この教材そのものが、GitHub を使って作られ、公開されています。あなたが今読んでいるページは、GitHub に置かれたファイルから作られています。

  • ページの下の「ソースを見る」から、教材のファイルを見られます。
  • 「変更の履歴を見る」から、いつ、誰が、何を変えたかを見られます。これが、Git の「履歴」の実物です。
  • 学習が進んだら、この教材の誤字や分かりにくい説明を、自分で直して提案する練習（Pull Request）にも使う予定です。

0-2. この教材でめざすこと（概要）

この教材は、まず一人で Git と GitHub を使いこなし、そのうえで、ほかの人と一緒にものづくり（共同開発）もできるようになることをめざします。プログラミングの経験がなくても、パソコンの基本から順番に進められるように作ってあります。一人でも、仲間と一緒でも学べます。

一人で使うだけでも、いつ・何を変えたかが記録に残り、いつでも前の状態に戻せるようになります。ほかの人と一緒に作るときは、誰が変えたかも記録し、みんなの変更をひとつにまとめることができます。それを担うのが Git と GitHub です。

最終ゴール

一人で（STEP 2）、次のことができるようになります。

  • ファイルの変更を記録し、GitHub に置いて、毎日続ける
  • 失敗しても、前の状態に戻す
  • 試しの作業を別の枝（ブランチ）で進め、うまくいったら取り込む

ほかの人と一緒に（STEP 3）、次のことができるようになります。人数は問いません。

  • 共有の置き場（GitHub のリポジトリ）に、自分の変更を送り、他の人の変更を取り込む
  • Pull Request で他の人に確認してもらってから、変更を取り込む
  • 同じ場所を変更して衝突（コンフリクト）しても、自分たちで解消する
一人で学んでいる人へ STEP 2 までは、すべて一人で進められます。一人で使いこなせるようになるだけでも、十分に役立ちます。STEP 3 も、公開されているリポジトリ（この教材など）に修正を提案する方法で、一人で体験できるようにしていきます。
この先にあるもの：AI と Git 最近は、AI に文書を書いてもらったり、作業の手順を整えてもらったりする場面が増えています。AI の道具の多くは、Git で管理されたフォルダの中で働くように作られています。AI がファイルを書き換えても、Git があれば、どこが変わったかを確かめ、気に入らなければ元に戻せます（第5章）。この教材で学ぶことは、AI を使って日々の作業を楽にするための土台にもなります。

0-6. 準備の流れ

準備の前に：「半角英数」と「日本語」の切り替えを練習する

この教材では、コマンドを、キーボードから打ちます。コマンドは、必ず半角英数（入力モード「A」）で打ちます。日本語入力（入力モード「あ」）のままだと、文字やスペースが全角（幅の広い文字）になり、コマンドが動きません。ここで一度、メモ帳で練習しておきましょう。

  1. キーボードの Windows キーを押し、「メモ帳」と入力して、検索結果の「メモ帳」を選んで、Enter を押す
  2. 画面右下（時計の左あたり）を見る。「A」か「あ」が表示されている
  3. キーボードの左上（Esc キーの下、数字の 1 の左）にある 半角/全角 キーを押す。押すたびに、「A」と「あ」が切り替わることを確かめる
  4. 「A」にして、git --version と打ち、Enter を押す
  5. 「あ」にして、同じキーを順に押す。ひらがなや、幅の広い文字が出て、下に線が付く（まだ確定していない状態）。Esc キーを何回か押すと、消える
  6. もう一度「A」に戻す。メモ帳は、保存せずに閉じて構いません（「保存しますか？」と聞かれたら、「保存しない」）
入力モード打った結果の例コマンドとして
A（半角英数）git --version動く
あ（日本語）「ぎｔ　ーーヴぇｒしおん」のように、ひらがなや全角の文字になる動かない
半角/全角 キーで切り替わらないとき 画面右下の「A」や「あ」の文字を、マウスでクリックしても、切り替えられます。それでも切り替わらないときは、メモ帳など、文字を打てる窓を一度クリックしてから、もう一度試してください（文字を打てる窓が選ばれていないと、表示が変わらないことがあります）。
迷ったら、まず「A」を確かめる これから先、コマンドを打つ前は、画面右下が「A」になっているかを見るくせをつけましょう。名前など、日本語を入れたいところだけ、一時的に「あ」にして、打ち終わったら「A」に戻します。

0-10. 「自分は誰か」と「使うエディタ」を Git に教える

Git は変更を記録するとき、誰が変更したかも一緒に記録します。そのため、最初に名前とメールアドレスを登録します。あわせて、Git が文字の入力を求めるときに開くエディタを、メモ帳に設定します。

ここで初めて、ターミナルを使います。詳しい説明は第2章で行うので、今は「書かれた通りに打つ」だけで大丈夫です。

  1. キーボードの Windows キーを押し、「windows powershell」と入力して、検索結果から「Windows PowerShell」を選んで、Enter を押す
  2. タブの付いた窓（Windows Terminal）が開き、文字を打つ画面が出る。これがターミナルです（色は、設定によって人それぞれです）
「PowerShell」と「Windows PowerShell」は、別のもの パソコンによっては、検索結果の一番上に「PowerShell」（新しい別の版。PowerShell 7）が出て、その下に「Windows PowerShell」が出ます（上の写真では、「Windows PowerShell」だけが出ています）。この教材は、Windows 11 に最初から入っている「Windows PowerShell」を前提にしています。一覧の中の「Windows PowerShell」を選んでください。
見分け方：開いた窓のタブに「Windows PowerShell」と出ていれば、OK です。「PowerShell」だけのときは、一度閉じて、選び直します。$PSVersionTable.PSVersion を打って、Major が 5 でも確かめられます。
「PowerShell」（7）で進めても、ほとんどの手順は動きますが、表示が一部、教材と違うことがあります（たとえば、日本語の文字化けの様子）。
コマンドは必ず「半角英数」で打つ 日本語入力がオン（「あ」の状態）のままだと、スペースや記号（「"」「-」）が全角になり、コマンドが動きません。打つ前に、画面右下（時計の左あたり）が「A」になっていることを確認してください。「あ」のときは、半角/全角 キーを押して切り替えます（0-6 の練習を参照）。名前の部分に日本語を入れるときだけ、一時的に日本語入力にします。

メールアドレスは、GitHub の「noreply アドレス」を使う

登録したメールアドレスは、これから作る記録（コミット）すべてに書き込まれます。公開リポジトリに送ると、誰でも見られます。公開されたアドレスを自動で集めるプログラムもあり、迷惑メールや詐欺メールが届く原因になります。

そこで、この教材では、ふだん使っているメールアドレスの代わりに、GitHub が用意している公開用の代わりのアドレス（noreply アドレス）を登録します。noreply アドレスでも、記録は、自分の GitHub アカウントに正しく結びつきます。先に、自分の noreply アドレスを調べます。

  1. ブラウザで GitHub にログインし、右上の自分のアイコンをクリックして、Settings を選ぶ
  2. 左のメニューから Emails を選ぶ
  3. 「Keep my email addresses private」にチェックを入れる
  4. そのすぐ下の説明文に出る、12345678+chitchi1216@users.noreply.github.com のような形のアドレスをコピーする（数字、+、自分のユーザー名、@users.noreply.github.com の順。数字は人によって違います）
非公開（private）のリポジトリしか使わないときも、noreply にしておく 非公開リポジトリの記録は、自分と、招待した人しか見られません。ただし、あとで公開に切り替えると、それまでの記録のアドレスも、すべて見えるようになります。また、--global の設定は、パソコンのすべてのリポジトリで使われます。最初から noreply にしておけば、公開・非公開を気にせずに済みます。

次の3行を、1行ずつ入力して Enter を押します。1行目と2行目は、中身が違います。取り違えないでください。

行設定する項目「 」の中に入れるもの
1行目user.name名前（ニックネームでよい。例：chitchi1216）。メールアドレスではありません
2行目user.email上で調べた noreply アドレス（…@users.noreply.github.com）。ふだん使っているメールアドレスではありません
3行目core.editorそのまま（notepad）
git config --global user.name "あなたの名前"
git config --global user.email "上で調べたnoreplyアドレス"
git config --global core.editor notepad

何も表示されなければ成功です。続けて、設定を確認します。

git config --global --list

次のように、入力した内容が表示されれば完了です（表示のイメージ）。

3行そろっているか、確かめる git config --global --list の表示に、user.name=…、user.email=…、core.editor=notepad の3行すべてがあることを確認してください（ほかの行が混ざっていても構いません）。
  • user.name にメールアドレスが入っている、または user.email の行がないときは、1行目と2行目を取り違えています。正しい内容で、もう一度同じコマンドを打てば、上書きされます。
  • user.email がないと、第3章の commit のとき、Committer: … configured automatically（「自動で設定されました」）という警告が出ます。記録は、できますが、名前やメールが正しく残りません。
すでに、ふだんのメールアドレスを登録していたとき 2行目のコマンドを、noreply アドレスでもう一度打てば、上書きされます。これから作る記録は、noreply アドレスになります。すでに作った記録のアドレスは変わりませんが、学習のうちは、そのままで構いません。
なぜエディタをメモ帳にするの？ Git の初期設定のエディタは、初心者には操作が難しい別のエディタ（Vim）になることがあります。うっかり開くと、閉じ方が分からず困る場面が多いので、使い慣れたメモ帳に先に設定しておきます。
うまくいかないとき git と打って、次のような赤い文字が出たら、Git が見つかっていません。

これは、コマンドの名前を打ち間違えたときにも出る、同じ形のエラーです（たとえば gitt と打つと、'gitt' として、同じ文言が出ます）。落ち着いて、綴りを確かめましょう。
全角の文字が混ざったときに出る表示 日本語入力のまま打つと、次のような表示が出ます。こういう表示が出たら、まず、入力モードが「A」になっているかを疑ってください。
  • git の部分が全角（ｇｉｔ）になった：上と同じ「用語 'ｇｉｔ…' は、…認識されません」が出ます。' と ' の間の文字が、幅の広い文字になっていることで見分けます。
  • git のあとが全角になった：Git から「… is not a git command」（Git のコマンドではありません）や、「unknown option」（知らないオプション）という英語の表示が出ます。
  • 名前を囲む " が全角（”）になった：エラーは出ませんが、git config --global --list で見ると、名前に ” が付いています。半角の " で、もう一度打てば、上書きされます。
直し方は、どれも同じです。半角/全角 キーで「A」に戻し、全部、打ち直します。キーボードの ↑ キーで前のコマンドを呼び出して直すより、打ち直すほうが確実です。

確認クイズ

Q1. Git と GitHub の違いは何ですか？

Git は変更履歴を記録する道具で、自分のパソコンの中で動く。GitHub は、その記録をインターネット上に置いて共有するサービス。

Q2. なぜ最初に名前とメールアドレスを登録するのですか？

Git が変更を記録するとき、誰が変更したかも一緒に記録するため。

Q3. コマンドを打つとき、日本語入力はどうしておくべきですか？

半角英数（入力モード「A」）にしておく。日本語入力のままだと、スペースや記号が全角になり、コマンドが動かなくなる。
