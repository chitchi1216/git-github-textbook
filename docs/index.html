Git と GitHub 入門

パソコンの基本から始めて、まず一人で Git と GitHub を使いこなし、そのあと、ほかの人と一緒に開発（共同開発）もできるようになるための教材です。一人でも、仲間と一緒でも学べます。環境は Windows 11 の PowerShell とメモ帳を使います。

⚠ 大切なお知らせ：アプリを最新版にしてください

2026年10月24日 時点の情報です。2026年10月に、インドの認証局 eMudhra の証明書に問題が見つかりました（悪用されると、偽の GitHub に気づかずつながってしまうおそれがあります）。同じ時期に、PHP の脆弱性も見つかっています。これから学ぶ人も、すでに学習を始めている人も、次のカードを確認してください。

全員 すでに Git を入れた人は、Git を最新版に

PowerShell で git --version を打ちます。2.56.0.windows.3 より古いときは、次のコマンドで更新します。

git update-git-for-windows

これから第0章で Git を入れる人は、教材の手順どおりに入れれば最新版になるので、この作業は不要です。

全員 Windows とブラウザも最新版に

「設定」→「Windows Update」で更新を確かめ、再起動します。Chrome や Edge は、一度閉じて開き直すと更新されます。主なブラウザと Windows は、問題の証明書をすでに使えなくしています。

VS Code を使う人 VS Code と拡張機能を最新版に

メニューの「ヘルプ」→「更新の確認」で更新します。拡張機能も、左の「拡張機能」の画面で更新があれば更新します。VS Code の Git の機能は、パソコンに入れた Git を使うので、上の Git の更新も必要です。

Claude Code を使う人 Claude Code（と Node.js）を最新版に

claude update で更新します。npm で入れた人は、Node.js も更新します。node --version で確かめ、22.23.4 / 24.22.1 / 26.12.1 より古ければ、Node.js の公式サイトから最新版を入れ直します。

AI を使う人・会社のパソコン 証明書のエラーを「確認しない」設定で消さない

SSL certificate problem などが出たとき、Claude Code などの AI やネットの記事が「確認を止める」設定（http.sslVerify false や NODE_TLS_REJECT_UNAUTHORIZED=0）を勧めることがあります。これは使わないでください。偽の相手を見分けられなくなります。アプリを更新しても直らないときは、表示をそのまま添えて管理者に相談します（第0章）。

PHP について この教材では、作業は不要です

見つかった PHP の脆弱性は、PHP で動く Web サーバーの問題です。この教材では PHP を使わず、教材のページも PHP を使っていません。ほかの用途で PHP を使っている人は、PHP を最新版（8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 以降）に更新してください。

参考：Git for Windows のリリース ／ gihyo.jp の解説（eMudhra）

この教材も、GitHub で作られています この教材のファイルも変更の履歴も、GitHub に置かれています。ページの下の「ソースを見る」「変更の履歴を見る」から、いつでも見られます。学習が進んだら、この教材の修正を提案する練習にも使います。 教材の GitHub ページを開く
この教材の進め方 基本は一人で読み進める自習です。第6章までは、すべて一人で進められます。仲間と一緒に学ぶ場合は、ときどき集まって、各章の「話し合おう・考えてみよう」を題材にディスカッションするのがおすすめです。一人で学ぶ場合は、同じ問いを、自分への質問として考えてみてください。

目次

  1. 第0章はじめに・準備教材の概要と対象者、GitHub アカウント、Git のインストールと初期設定
  2. 第1章パソコンの仕組みファイルとフォルダ、パス、OS とアプリ、クラウドとは
  3. 第2章ターミナル入門エクスプローラーの操作とコマンドを見比べて、文字で操作する画面に慣れる
  4. 第3章Git の基本：記録をつくるinit / status / add / commit / log / diff で、変更を記録して履歴を見る
  5. 第4章GitHub と連携する：送る・受け取るclone / push / pull で、自分のパソコンと GitHub の間で記録をやりとりする
  6. 第5章一人で使いこなす：毎日の流れ・履歴を読む・取り消す.gitignore / show / restore / revert で、一人で安心して毎日使えるようにする
  7. 第6章ブランチ：作業を枝分かれさせるbranch / switch / merge で、試しの作業を分けて、あとで合流させる
  8. 第7章Pull Request準備中ブランチを切って PR を出し、レビューを受けてマージする
  9. 第8章コンフリクトの解消準備中衝突をわざと起こして、自分で直す
  10. 第9章共同開発演習準備中ほかの人とルールを決め、Issue から PR まで一周する（一人の場合は、公開されているリポジトリへの修正提案で体験する）
